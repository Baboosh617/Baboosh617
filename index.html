I started where most developers do: HTML, CSS, and some JavaScript that didn't quite work the way I expected. What kept me going wasn't the code, it was the feeling of building something that actually responded to the world.

That curiosity pushed me deeper: Django and FastAPI for backend work, PostgreSQL for real data persistence, Redis and Celery for the jobs that shouldn't block a request, and eventually machine learning. I built a power grid stability predictor that hit 98.7% accuracy. Not because I followed a tutorial, but because I spent time understanding why the data looked the way it did.

Right now I'm working in the space between software engineering and AI. The most interesting work happens where infrastructure meets intelligence: a system that doesn't just run, but learns. That's where I want to be.

// 06 — Approach

How I approach problems

  1. 01

    Understand the system

    Map the problem first. No code until the logic is clear.

  2. 02

    Break it into parts

    Isolate each piece, test it, then put them back together.

  3. 03

    Iterate until stable

    Ship early, refine on real feedback, skip premature perfection.
